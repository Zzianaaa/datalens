# DataLens · 经营数据工作台

**从 CSV 分析到库存、履约与收付款，把经营数据放进一套可核对的流程。**

DataLens 是一个可在本机运行的单用户经营管理应用。你可以导入自己的 CSV，清洗和分析数据，也可以手工登记采购、销售、费用与业务任务。核心功能无需模型 API 或付费服务。

> 当前版本：`0.12.0`。适合个人使用与项目演示；尚无账号系统或多用户权限隔离。**仓库地址不是线上应用地址，请勿把保存真实业务数据的实例直接暴露到公网。**

## 功能概览

| 工作区 | 可以做什么 |
| --- | --- |
| 分析工作台 | 导入 CSV、搜索排序、质量检查、预览清洗副本、SQL 查询、图表和报告导出 |
| 项目与数据中心 | 组织项目，保存数据快照与分析报告，归档、恢复并重新打开分析 |
| 经营测算 | 根据单价、成本、销量计算收入、利润与盈亏平衡销量，对比方案 |
| 业务目标与任务 | 记录目标进度、负责人和截止日期，筛选任务、流转状态与归档 |
| 库存与采购 | 商品和库存流水、补货覆盖、采购交期、分批到货与库存核对 |
| 销售与履约 | 多商品订单、分批发货、缺货核对、关闭未发余量与批次对账 |
| 应收与应付 | 分次登记收付款、账龄、客户与供应商汇总、误录冲销与跟进任务 |
| 费用与预算 | 记录经营支出、按项目或收款方汇总、费用作废、月度预算执行 |
| 总览与预警 | 查看收支趋势、收付款到期安排、缺货及到期事项，跳转对应台账 |
| 指标模板 | 保存业务口径与只读 SQL，切换数据后复用 |

### 两条常用流程

**分析一份数据**：上传 CSV → 查看质量报告 → 预览并应用清洗 → 核对经营指标或 SQL → 导出结果 → 保存快照和报告。

**处理一笔业务**：创建采购 → 登记到货，更新库存并按已填成本形成应付 → 销售发货，扣库存并形成应收 → 手工登记收付款 → 核对余额与流水。

CSV 分析与经营台账分开管理。上传文件、保存报告不会自动增加库存、创建订单或登记收付款。

## 快速启动

需要 **Python 3.11+、Node.js 22.12+、pnpm 11.25.0**。在仓库根目录执行以下命令（macOS / Linux）：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

cd frontend
pnpm install --frozen-lockfile
pnpm run build
cd ..

uvicorn backend.app:app --host 127.0.0.1 --port 8000 --workers 1
```

Windows 可用 `py -m venv .venv` 创建环境，在 PowerShell 执行 `.venv\Scripts\Activate.ps1` 激活，再执行安装、构建和启动步骤。

打开 [本机工作台](http://127.0.0.1:8000)，点击 **加载示例数据** 即可体验。示例订单是虚构数据。

前端开发可在 `frontend/` 运行 `pnpm run dev`，后端仍需单独启动。更新前端后，重新构建并重启后端；本应用使用单个后端进程，分析会话不在进程间共享。

## 查询模式

| 模式 | 适用范围 | 是否需要模型 |
| --- | --- | --- |
| 规则演示 | 界面列出的四个示例问题，需要相应示例字段 | 否，不是 AI 推理 |
| SQL 查询 | 当前 CSV，表名为 `data`；可从字段模板开始 | 否 |
| AI 自由提问 | 可选的兼容 Chat Completions 服务 | 需要自行配置，默认未启用 |

例如，选择 SQL 模式后运行：

```sql
SELECT COUNT(*) AS "记录数" FROM data
```

中文或带空格的字段名使用双引号。查询仅支持当前表的受限只读 SQL；不支持 JOIN、子查询、CTE 或窗口函数。结果最多返回 200 行，图表最多展示前 50 条有效数值。

AI 适配器已经实现，但**尚未完成真实模型在线验收**。如自行配置，服务端读取 `LLM_API_KEY`、`LLM_MODEL` 和可选 `LLM_BASE_URL`；发送字段名称、类型和问题，不发送原始数据行。不要将密钥写进前端或提交到仓库。

## 数据保存

| 数据 | 保存位置与有效期 |
| --- | --- |
| 上传的 CSV、清洗副本 | 服务内存，最多一小时；后端重启会丢失 |
| 项目、已保存快照与报告、经营台账、模板 | 本机 SQLite，服务重启后保留 |
| 查询历史、测算对比方案 | 当前页面内存，刷新后清空 |
| 当前分析数据标识 | 浏览器本地存储；只能恢复服务端尚未过期的数据 |

需要长期保留 CSV 时，在 **项目与数据中心 → 保存当前分析数据** 保存快照。临时会话失效后，可以重新打开已保存快照。

默认数据库为 `storage/platform.sqlite`，可在启动前通过 `DATALENS_DB` 指定其他路径。备份时先停止服务，再复制数据库；恢复时停止服务并将 `DATALENS_DB` 指向备份副本。**不要把数据库、备份、真实业务文件或密钥上传 GitHub。**

上传限额：每份 5 MB、20,000 行、50 列，同时最多保留 10 份临时数据。数据中心最多 50 个项目、100 份快照（合计 100 MB）、100 份报告（每份 2 MB）。

## 计算口径与使用限制

- 台账金额以整数分保存、以元展示。收付款为手工记录，不发起银行转账，也不验证银行到账。
- 经营看板按每行金额求和，不再乘数量；行数不是去重订单数。无效日期不计入月度趋势，但金额仍计入合计。
- 总览台账收付净额＝有效回款－供应商已付－有效经营费用，不等于利润或银行余额。同一采购付款不要再次登记为经营费用。
- 清洗生成副本，已保存快照不随之后的清洗改变。冲销或作废保留原记录，适用于误录纠错，不代表实际退款。
- 待到货不能用于发货；库存不预占，不自动向供应商下单。不同商品或单位的数量不能直接互相抵扣。
- 目标进度手工维护，预警在进入或刷新页面时计算；不提供后台监控、自动通知或自动完成任务。
- SQL 校验通过不代表业务口径正确。查询在受限 DuckDB 子进程执行，但目前没有账号、租户隔离或公网服务所需的完整访问控制。

## 开发与验证

技术栈：**Vue 3 · ECharts · FastAPI · SQLite · DuckDB · SQLGlot**。前端构建后由 FastAPI 同源提供页面和 `/api` 接口，运行时不依赖外部图表 CDN。

```bash
# 仓库根目录，已激活 Python 环境
python -m pytest -q

# 前端测试与构建
cd frontend
pnpm test
pnpm run build
```

测试覆盖查询约束、金额与库存事务、幂等重试、冲销、筛选导出和异步响应隔离；GitHub Actions 执行后端测试、前端测试及构建。模拟模型测试不代表真实 AI 准确率，最新细节见 [VALIDATION.md](VALIDATION.md)。

## 部署与域名

域名需要指向**能运行 Python 后端、提供 HTTPS 并保存 SQLite 数据**的服务。只发布前端静态文件不能运行完整平台。

中国大陆访问方案、域名解析步骤与上线条件见 [部署说明](docs/DEPLOYMENT.md)。当前尚未配置或验证线上应用域名。
